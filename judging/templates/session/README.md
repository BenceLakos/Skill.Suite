# SkillSuite.Session

A Skill Suite judging session module, generated from the `skillsuite-session` template.

```
SkillSuite.Session.Contracts/    the interface a competitor implements, packed to local-nuget/
SkillSuite.Session.Services/     the reference implementation — the answer key
SkillSuite.Session.UnitTests/    the hidden graded suite, one [Aspect] per test case
competitor-start/                GENERATED by make-competitor-start.sh — never edit by hand
marking-map.json                 aspect ids and labels; scoring dials for a black-box session
Dockerfile                       white-box judge image (competitor implements the services)
Dockerfile.blackbox              black-box judge image (competitor writes the tests)
```

## First run

```bash
chmod +x pack-contracts.sh build-image.sh make-competitor-start.sh docker-entrypoint.sh
```

The template cannot set the execute bit itself — a post-action that could makes `dotnet new` prompt for
`--allow-scripts` and hang in CI.

```bash
JUDGING_ROOT=/path/to/judging ./pack-contracts.sh
```

Fills `local-nuget/` with this module's Contracts package plus the three judging packages. Required before any
build: the image restores offline and fails `NU1101` without it. If this module lives in its own repository,
set `JUDGING_FEED=<nuget source>` instead. `JUDGING_ROOT` is discovered automatically when the module sits
inside the judging tree.

## Regenerate the competitor starter kit

```bash
JUDGING_ROOT=/path/to/judging ./make-competitor-start.sh            # white-box
JUDGING_ROOT=/path/to/judging ./make-competitor-start.sh blackbox   # black-box
```

Derives `competitor-start/` from whichever folder the judge swaps at run time, as it stands right now, and then
compiles it to prove it builds against the current contract. Run it whenever the contract or the reference
changes, and before handing anything out.

The two modes are inverses because the two session types are. **White-box** strips the `*.Services`
implementation: public members keep their exact declaration with a `NotImplementedException` body, non-public
members and non-const fields go. **Black-box** empties the `*.UnitTests` reference suite: every method goes —
the tests *are* the answer — while the harness wiring stays, because a private field holding
`ServiceResolver.Resolve<T>().WithCallLogging()` is plumbing, not the answer. Removing it would leave a project
that cannot resolve the service under test.

It is generated rather than checked in for one reason: a hand-maintained starter kit drifts the moment you
touch the implementation, and the drift stays invisible until a competitor cannot compile what they were given.
Anything you edit inside `competitor-start/` is lost on the next run — the directory is recreated, not merged,
so a stub for a member you have since deleted cannot survive into what competitors receive.

Either way the type's own doc comment is replaced — on a reference implementation it describes the answer key,
and on a reference suite it says "calibration only", both of which are hints once the competitor is reading them.

## Calibrate before building

```bash
dotnet test SkillSuite.Session.sln
```

The hidden suite must score **100%** against the reference implementation. A session whose own answer key does
not pass is not ready — every competitor would lose the same marks for your bug.

## Build the judge image

```bash
./build-image.sh
```

```bash
./build-image.sh blackbox
```

No session-specific arguments. The solution name, the folder that gets swapped and the test project are `ENV`
in the Dockerfiles, because they are facts about this module rather than choices the caller makes. Only
environment-dependent values are settable:

| | |
|---|---|
| `BASE_IMAGE=skill-suite-judge-base:9.0` | a locally built base instead of the published one |
| `TAG=1.0.1` | overrides the image tag |
| `REGISTRY=<host>/<owner>` | prefixes the name for pushing |
| `NO_CACHE=1` | `docker build --no-cache` |

## Publish from Gitea

`.gitea/workflows/publish-session.yml` does the whole publishing pass on a push to `main` or a `v*` tag, on
the runner attached to the competition's docker host: `pack-contracts.sh`, the hidden suite against the
reference (a red test stops everything), `make-competitor-start.sh` in both modes, `build-image.sh both`, a
push of both images to Gitea's registry under `sha-<commit>` or the version tag, and a copy of both kits into
the platform's `skill-suite-starter-packages` volume as `<repository>/competitor-start` and
`<repository>-blackbox/competitor-start`. It prints the image references and template folders to register
in the UI; starting a session stays a manual step. Publish the repository with the platform's
`scripts/gitea-push.sh`, which also stores the registry token the workflow needs, and see the header of the
workflow for the optional variables (`REGISTRY`, `JUDGING_FEED`, `BASE_IMAGE`, `STARTER_PACKAGE_NAME`).

The judging packages and `judge-base` it restores and builds from come from the platform repository's
`publish-judging` workflow, which puts them on the same Gitea under the platform's owner. Run that once
before the first session publish, and set `JUDGING_FEED` / `BASE_IMAGE` on this repository if that owner
differs from this one. A plain-http `JUDGING_FEED` works: the scripts mark the source insecure for NuGet.

## Run a submission without the platform

```bash
judging/tools/judge-run.sh skillsuite-session-judge:1.0.0 ./some-submission
```

Mirrors `ProcessContainerRunner` exactly — read-only mount at `/workspace`, `-w /workspace`, two env vars —
and prints the exit code and resulting events. A submission is a directory containing just the swapped folder:
`SkillSuite.Session.Services` for white-box, `SkillSuite.Session.UnitTests` for black-box.

In a white-box session, red tests are a **result**, not a failed run: expect exit 0 with failures recorded.

## Writing the graded suite

`SkillSuite.Session.UnitTests/CalculatorTests.cs` is the required shape. Three rules the harness enforces:

- Derive from `LoggedTest<TSelf>` and take `IClassFixture<FixtureScope<TSelf>>`. Without the fixture there is
  no start/finish-fixture pair and the platform records nothing at all.
- Assert through `Log`, never bare `Assert`. A bare assertion fails the test but emits no event, so the result
  arrives as a red row with nothing explaining it.
- Resolve with `ServiceResolver.Resolve<T>().WithCallLogging()`. The proxy records every call with arguments
  and return value, which is what makes a disputed mark reviewable, and enforces the nullability declared on
  the interface.

One test case is one aspect, and an aspect is satisfied only when **every** test claiming it passes — so a
`[Theory]` with five rows is all-or-nothing. Split it when the rows should score separately.
`CompetitorVisible = true` lets an aspect move the coarse bar the competitor sees; leave it off to grade
without revealing anything.

## Black-box specifics

The pipeline in `docker-entrypoint.sh`:

```
swap_dir → restore_offline → build_tests → run_tests (trx + cobertura)
        → stryker (LOG_DIRECTORY redirected) → skill-marker score
```

`stryker-config.json` is deliberately terse and carries no comments. Stryker validates its keys against a
fixed allow-list and **fails the whole run on an unrecognised key**, so the `"// note": "..."` trick used in
`marking-map.json` cannot be used there. The reasoning that would otherwise be comments:

- **`reporters: ["json"]`** only — the marker reads `mutation-report.json`, and the HTML reporter would bloat
  the image for nobody.
- **All thresholds 0.** Stryker must never decide pass or fail. Scoring belongs to the marker, driven by this
  module's `marking-map.json`, so the constants can be re-tuned without rebuilding the image.
- **`concurrency: 2`.** Containers get no CPU limit by default and the platform's judge worker is bounded, so
  leaving headroom matters more than finishing fast.
- **`additional-timeout: 5000`** is the per-test-run budget in milliseconds; the outer wall clock is
  `JUDGE_MUTATION_TIMEOUT_SECONDS`, enforced by the entrypoint.

Stryker re-runs the whole suite once per mutant, and every one of those test hosts inherits `LOG_DIRECTORY`
and opens `events.jsonl` with `FileMode.Create`. The entrypoint redirects them to a throwaway directory rather
than merely unsetting the variable — unsetting was not enough in practice, and the result was `events.jsonl`
interleaved from several truncating writers: the right length, full of NUL bytes, with every real test event
gone.

## Two things that will bite

**Never use a mutable tag.** The platform runs `docker run` with no `--pull`, so re-pushing `:latest` leaves
it judging with a stale local image.

**These images are secret.** The white-box image contains the hidden tests; the black-box image contains the
reference implementation *in source form*, because Stryker has to mutate it. Private registry only, never
public CI. The builds fail on purpose if the answer key reaches the wrong image — do not "fix" that by
loosening the dockerignore.
